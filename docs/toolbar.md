# The formatting toolbar and Format Cells

## `SheetToolbar`

`SheetToolbar` is Excel's formatting toolbar over the same source, in the order of Excel for Windows' ribbon: Undo and Redo, the Font and Font Size boxes with Increase and Decrease Font Size, Bold, Italic, Underline with its menu, Borders, fill and font colors from Excel's palette, Top, Middle and Bottom Align, Orientation with its menu, horizontal alignment, Decrease and Increase Indent, Wrap Text, Merge & Center, Excel's Number Format box with Accounting Number Format and its menu of currencies, Percent Style, Comma Style, Increase Decimal and Decrease Decimal, for a host that displays the dialog ([below](#formatdialog)) Format Cells, and with `sheet` Excel's AutoSum. It formats the selection reported by the sheet's `state` event through `format(sheet, patches)`, as Excel formats a selection: Bold applies on top of each cell's formatting, and Outside Borders is four patches in one call and therefore a single undo step. Its buttons show as pressed according to the active cell's formatting, and clicking a pressed button removes that formatting, as in Excel. The toolbar is shown only when the source has `format`; Undo and Redo appear when the source has `undo` and `redo`, and are disabled while its `history` (the local source's) has no steps.

Borders is Excel's split button: its part applies the border picked last, Bottom Border until another is picked, and is named after it (`border-last`), and its arrow (`borders`, named Borders) opens the menu with Bottom Border, No Border, All Borders and Outside Borders, in Excel's order with Excel's line after Bottom Border. Excel's other items (Top, Left, Right and the thick and double borders, drawing, More Borders...) are not there; the Format Cells dialog's Border tab draws any edge.

Underline is Excel's split button too, as measured in Excel for Windows: its part (`underline`) applies the underline picked last from its menu, Underline until Double Underline is picked, and is named after it (`underline`, `Underline (Ctrl+U)`, then `underlineDouble`); it shows as pressed while the active cell has that underline, and clicking it then removes it, while on a cell with the other underline it puts its own in that one's place. Its arrow (`underline-menu`, named `underlineMenu`) opens the menu with Underline and Double Underline (`underline-single`, `underline-double`, the texts `underlineSingle` and `underlineDouble`), each checked while the active cell has it; an item picked on a cell that has its underline removes it, as in Excel. Below 600 px the arrow is not drawn, so that Bold, Italic and Underline keep their place in the row; Double Underline is on Format Cells' Font tab there. Ctrl+U on the grid is Excel's key, not the part: it sets a single underline unless the active cell's is single, which it removes, so a double underline becomes single; the whole selection gets the result, as in Excel (xlcalc's table in its `docs/edits.md`, measured in Excel for Windows). A file's single and double accounting underlines reach the sheet as single and double, and Ctrl+U gives them what Excel does: none and single.

Accounting Number Format is Excel's split button: its part applies Excel's built-in format 44, as before, and its arrow (`accounting-menu`, named `accountingMenu`) opens Excel's list of currencies for an Excel whose interface and regional format are the workbook's locale: in en-US $ English (United States), £ English (United Kingdom), € Euro (€ 123), ¥ Chinese (Simplified, Mainland China) and CHF French (Switzerland); in ru-RU ₽ русский, £ английский (Соединенное Королевство), € Евро (€ 123), ¥ Китайский, упрощенное письмо (континентальный Китай) and CHF французский (Швейцария); in a locale without the package's module en-US's list. The list, its names and its codes are xlcalc's `accountingFormats` (0.75.0, `xlcalc/text`), so the names are in the workbook's language, as in an Excel run in it, whatever texts the toolbar has; in ru-RU they appear once the locale's module has loaded, as the Number Format box's list does. The hooks are `accounting-usd`, `accounting-rub`, `accounting-gbp`, `accounting-eur`, `accounting-cny` and `accounting-chf`. Each applies the code Excel writes for it in the workbook's locale, measured in Excel for Windows with en-US and with ru-RU regional settings: the dollar's is `_([$$-409]* #,##0.00_);_([$$-409]* (#,##0.00);_([$$-409]* "-"??_);_(@_)`, the ruble's `_-* #,##0.00 [$₽-419]_-;-* #,##0.00 [$₽-419]_-;_-* "-"?? [$₽-419]_-;_-@_-`, the pound's, the yuan's and the franc's are the same in both, and the euro's follows the locale's negatives (`_([$€-2] * #,##0.00_);...` in en-US, `_-[$€-2] * #,##0.00_-;...` in ru-RU). The Number Format box then names Accounting, after the part and after each currency, as Excel's does in en-US and ru-RU: xlcalc (0.75.0) names every code of the menu Accounting, and the built-in 44, which reaches the sheet as its code, by its number. After a line, More Accounting Formats... (`accounting-more`, `accountingMore`) opens Format Cells on the Number tab with its Accounting item picked, as Excel opens it at the Accounting category, so that OK applies the built-in 44 ([below](#formatdialog)); it is there when the dialog is (with `sheet` or a host that listens to `formatCells`).

The list is the owner's rule, that of an Excel run in the workbook's language: Excel's own list follows its interface language and the regional format it runs with, and the languages Windows has, not the workbook. Measured in Excel for Windows on a machine with Russian and English installed: a Russian interface with ru-RU format lists ₽, £, €, ¥, CHF, the list the toolbar takes for ru-RU; an English interface with en-US format lists $, ₽, £, €, ¥, CHF, the ruble added for the Russian Windows has, which the toolbar's en-US list leaves out; mixed, an English interface with ru-RU format lists ₽, $, £, €, ¥, CHF, a Russian one with en-US format $, ₽, £, €, ¥, CHF. A browser does not tell which Excel its user would have, so the toolbar does not follow these mixes.

Orientation is Excel's button with a menu, between Top, Middle and Bottom Align and the horizontal alignments (the group `orientation`): its items Angle Counterclockwise, Angle Clockwise, Vertical Text, Rotate Text Up and Rotate Text Down (`orientation-counterclockwise`, `orientation-clockwise`, `orientation-vertical`, `orientation-up`, `orientation-down`, the text `orientationKind`) turn the selection's text as Excel does, to `alignment.rotation` 45, -45, `'vertical'`, 90 and -90 ([below](#rotated-text)); the one the active cell has is checked, none at other degrees, and picking it again returns the text level, as in Excel. After a line, Format Cell Alignment (`orientation-format`, `orientationFormat`) opens Format Cells on the Alignment tab, when the dialog is there. The button's hook and text are both `orientation`.

The three menus close on Esc, a pick or a click elsewhere, as the toolbar's other menus do, and their buttons are disabled where the sheet cannot be formatted.

With `sheet` and the source's `structure`, the toolbar has Excel's Merge & Center: the button merges the selection and centers its contents, and its dropdown has Merge & Center, Merge Across, Merge Cells and Unmerge Cells, each a single undo step through the sheet's `merge(command)`. The button shows as pressed on a merged cell, and clicking it then unmerges, as Excel's does; on a single cell outside a merged range it does nothing, and it is disabled on a read-only sheet and under a display filter. Before a merge that would keep only one of several values in a range (in a row, for Merge Across), the sheet shows Excel's warning "Merging cells only keeps the upper-left value and discards other values.", with OK on Enter and Cancel on Esc; it counts the cells that contain a value or a formula in its loaded windows, or in the source's windows over the range when the loaded ones do not cover it. If the source rejects the merge, its message is displayed.

With `sheet`, the toolbar has Excel's AutoSum from Home > Editing, a split button like Merge & Center: Σ enters Sum in the active cell through the sheet's `autoSum()`, opening its edit with `=SUM(range)` and the range selected ([editing.md](editing.md#autosum)), and its dropdown lists Sum, then Average, Count Numbers, Max and Min as the source lists them in `autoSumFunctions` (`./local` lists all four), and More Functions…, which opens the sheet's Insert Function dialog (`insertFunction()`) for a source with `functionNames`. Both parts are disabled while `state.canAutoSum` is absent: without the source's `autoSum` and on a read-only sheet. Its texts are `autoSum`, `autoSumMenu`, `autoSumSum`, `autoSumAverage`, `autoSumCount`, `autoSumMax`, `autoSumMin` and `autoSumMore`.

With `sheet` and the source's `structure`, the toolbar has Excel's Insert > PivotTable, which opens the sheet's PivotTable from table or range dialog through `insertPivotTable()` ([pivot-tables.md](pivot-tables.md#insert-pivottable)); it is disabled while `state.canInsertPivot` is absent, on a read-only sheet. Its text is `pivotInsert`.

With `sheet` and the source's `refreshConnections`, the toolbar has Excel's Data > Refresh All, a split button as on Excel's Data tab: the button asks every call outside the workbook again and refreshes the PivotTables through the sheet's `refreshAll()` ([calculation.md](calculation.md#refresh-all)), and its dropdown lists Refresh All and Refresh, which refreshes the PivotTable under the active cell through `refreshPivot()` ([pivot-tables.md](pivot-tables.md#refresh-and-refresh-all)). The button and Refresh All are disabled while `state.canRefreshAll` is absent, on a read-only sheet; Refresh while `state.canRefreshPivot` is absent. Its texts are Excel for Windows' ScreenTip, `refreshAll`, the name with its key (`Refresh All (Ctrl+Alt+F5)`, `Обновить все (Ctrl+Alt+F5)`), over `refreshAllTip`, its description (`Get the latest data by refreshing all sources in the workbook.`, `Получение новейших данных путем обновления всех источников в книге.`), shown under the name as Office shows it; `refreshAllMenu`, the dropdown's button and list, named Refresh All as Excel names its list; `refreshAllItem` and `menuRefresh` (the items, whose tooltips are `refreshAll` and `refreshPivot`, Refresh's with its key, `Refresh (Alt+F5)`).

```vue
<script setup lang="ts">
import { onUnmounted, ref } from 'vue'
import { SheetToolbar, SheetView, type SheetViewApi, type SheetViewState } from '@xlcalc/vue'
import { localSource } from '@xlcalc/vue/local'
import '@xlcalc/vue/style.css'

// A source with format, undo and structure: the toolbar is shown only for a source with format
const source = localSource({
  sheets: [{ name: 'Sheet1', cells: { A1: { value: 'Region' }, B1: { value: 'Sales' }, A2: { value: 'North' }, B2: { value: 0.125 }, A3: { value: 'South' }, B3: { value: 0.3 } } }],
})
onUnmounted(() => void source.close())

const state = ref<SheetViewState | null>(null)
const sheet = ref<SheetViewApi | null>(null)
</script>

<template>
  <SheetToolbar :source="source" :sheet="sheet" :state="state" />
  <SheetView :source="source" ref="sheet" style="height: 360px" @state="state = $event" />
</template>
```

The toolbar formats the selection, every range of a selection of several (`state.areas`) as Excel does. The Font and Font Size boxes show the active cell's font and size, and each takes a typed value or a pick from its list: Enter or a pick applies it to the selection, and Esc, or leaving the box without Enter, restores what it showed (Esc also emits `done`, so the host can return focus to the grid). A cell without its own font or size shows the workbook's default font (`state.font`, from the source's `SheetInfo.font`), and empty boxes when the source does not give one. A browser does not tell which fonts are installed, so the Font box's list is Excel's common fonts (Aptos, Aptos Narrow, Arial, Calibri, Cambria, Consolas, Courier New, Georgia, Segoe UI, Tahoma, Times New Roman, Verdana), each drawn in its own font, and the `fonts` prop replaces it; any name may be typed, and typing completes it with the first font of the list it begins, as Excel's box does. The Font Size box's list is Excel's (8 to 72), and it takes any size from 1 to 409, with a decimal point or comma, rounded to half points (Excel takes sizes in multiples of .5); any other text stays in the box, marked invalid with the message `fmtSizeRange`, until it is corrected or Esc restores the box. The arrows go through the list, putting each item into the box.

Increase and Decrease Font Size step the active cell's size (11 points for a cell without one, the size the grid draws it at) through Excel's list, beyond 72 in steps of 10 up to 409, and below 8 a point at a time down to 1, and set the new size over the selection; at a limit they send nothing. Top, Middle and Bottom Align show as pressed according to the active cell's vertical alignment, Bottom for a cell without one (Excel's default); clicking a pressed one returns the selection to Bottom. Increase Indent adds a level to the active cell's indent and keeps the Left, Right and Distributed alignments, which have an indent, while any other alignment (General, Center and the rest) becomes Left, as in Excel; Decrease Indent takes a level off without changing the alignment, and does nothing at 0 or with an alignment that has no indent. Indents go up to 250 levels. Percent Style sets Excel's `0%` (the built-in format 9) over the selection, as Ctrl+Shift+% on the grid does ([editing.md](editing.md)); the Number Format box then names Percentage. Accounting Number Format and Comma Style set Excel's built-in formats 44 and 43, which display in the workbook's locale (its currency for Accounting). Increase Decimal and Decrease Decimal take the active cell's format, value and column width (`state.numberFormat`, `cellValue`, `columnWidth`) through xlcalc's `stepDecimals`, as Excel for Mac steps them (a General cell takes the decimals it shows, one more or one less; a code takes a decimal in each section), and put the result on the whole selection, as Excel does; when the step changes nothing (General without a number, no decimal to take away) nothing is sent.

The Number Format box works as Excel's does, as measured by xlcalc (`numberFormatCategory` and `numberFormatChoices` of `xlcalc/text`, without the engine): it shows the category of the active cell's format (General if there is none, Custom where no Excel category matches the code), and its list applies Excel's eleven items (General, Number, Currency, Accounting, Short Date, Long Date, Time, Percentage, Fraction, Scientific, Text), each with the format Excel sets (Percentage is `0.00%`), after which the box shows the new category. It is drawn as the Font box is, a field joined to its arrow in a cell of its own, as wide as its longest category name (`Экспоненциальный` in ru-RU), and its list is the toolbar's own: a click on the field or the arrow (`number`, `number-list`), or Alt+↓ in the field, opens it with the item marked whose format the active cell has, by its code (General for a cell without one; none for a code no item applies, such as `0%`, a date or time of the cell's own or Custom, and Enter then closes the list for the grid, as Esc does), the arrows go through it, the field naming each item they reach to a screen reader (`aria-activedescendant`), and Enter or a click on an item (`data-tb-number`, the item's key: `general`, `percentage`, `shortDate`...) applies the item; Esc closes it and emits `done`. As Excel's, the list shows all its items without scrolling (below 600 px it ends within the screen and scrolls, as the Font boxes' lists do: each list ends at the viewport's bottom wherever it opens), and after a line More Number Formats... (`data-tb-number="more"`, `numberFormatMore`), which opens Format Cells on the Number tab at the active cell's format, as Ctrl+1 does; it is there when the dialog is (with `sheet` or a host that listens to `formatCells`, which gets `{ tab: 'number' }`). The field shows the category and takes no typing. As Excel for Windows' list, each item shows under its name a sample of the active cell's value (`cellValue`) in its format (`.xs-tb-item-note`): No specific format (`Формат не указан`) under General, the value in the item's format under the others (`25.00%` under Percentage), ten `#` for a value the format cannot show, nothing under the others for an empty cell. The samples are xlcalc's `numberFormatSamples` (0.78.0), measured in Excel for Windows: they depend on neither the cell's own format nor its column's width, and dates follow the source's `dateSystem` (1904 for a workbook in 1904). They come from `xlcalc/entry`, a separate chunk loaded as the list first opens, so the first opening may show the names alone for a moment; a chunk that fails to load leaves the names alone, and is asked for again when the list next opens or the active cell changes under it. A screen reader hears an item's name, its sample as its description (`aria-description`). Excel's icons are not drawn. The workbook's locale is the sheet's (`state.locale`), else the source's `locale`, so the host passes none; the `locale` prop overrides it. The category names and the Currency item's code follow it, with ru-RU's data loaded as a separate chunk; without any, en-US ([api.md](api.md#locales)). With `sheet` (the sheet's template ref), the toolbar formats, undoes and redoes through the sheet's methods ([api.md](api.md#sheetviewapi)), and the sheet sets the selection and displays a rejection itself. Without it, the toolbar calls the source and emits `select` with where the selection goes after an undo or a redo (for the sheet's `focus`) and `error` with the source's rejection. It emits `done` after each call, so the host can return focus to the grid. Its buttons do not take focus from the grid; the font boxes and the Number Format box do, while they are used. It keeps what fits in one row, or in the lines `rows` allows, and moves the rest into a menu under More ([below](#choosing-the-buttons)); below 600 px or on a touch screen every target is 44 × 44 px. Its buttons and boxes have Excel's ScreenTips instead of the browser's `title`: the name and the key (`Bold (Ctrl+B)`, from `SheetMessages`) below the control after the mouse rests on it for 0.4 s, and at once on the next one within 0.6 s, disabled buttons included; a press, a menu opening or the mouse leaving hides it, and touch gets none. The text is each control's `data-tip` (its `aria-label` names it too), and a host's button shows its `label`.

The names of the buttons and boxes, in English and in Russian, are those of Excel for Windows' ribbon (`Font Color`, `Цвет шрифта`; `Выровнять по верхнему краю`; `Переносить текст`; the Font Size box's `Размер`; AutoSum's `Count Numbers`, `Счетчик`), with the key after the name where Excel's ScreenTip gives one. Two keep their own: Redo is `Вернуть (Ctrl+Y)` in Russian, since Excel's name for that button on its Quick Access Toolbar changes with the history and was measured only without steps to redo, and PivotTable Analyze's Options is `PivotTable Options` (`Параметры сводной таблицы`), since the toolbar is one strip without Excel's contextual tab that would tell which Options it is. Format Cells' Wrap Text box has its own text, `fmtWrap` (`Wrap Text`, `Перенос текста`), since the dialog's Alignment tab has not been measured.

### Choosing the buttons

The `items` prop picks the toolbar's groups and their order, and adds the host's buttons among them. Without it the toolbar draws every group in the default order, `TOOLBAR_GROUPS`, which is Excel for Windows' ribbon: Undo and Redo from its Quick Access Toolbar, Home's groups in Home's order (Clipboard, Font, Alignment, Number, Editing), then the commands of other tabs in the tabs' order. The groups are `undo`, `formatPainter` ([Format Painter](clipboard.md#format-painter), with `sheet`), `font` (the Font and Font Size boxes with Increase and Decrease Font Size), `fontStyle` (Bold, Italic, Underline), `borders`, `colors` (Fill Color, then Font Color), `verticalAlign`, `orientation`, `align` (horizontal alignment, indent and Wrap Text), `merge`, `number` (the Number Format box and its buttons), `formatCells` (after the Number group, where Excel has the group's dialog launcher), `autoSum`, `pivotTable` (Insert > PivotTable, with `sheet` and the source's `structure`), `refreshAll` (with `sheet` and the source's `refreshConnections`), and `pivotAnalyze` and `pivotDesign` (Excel's PivotTable Analyze and Design commands, shown with `sheet` and the source's `pivotCells` while the active cell is in a PivotTable, [pivot-tables.md](pivot-tables.md#pivottable-analyze-and-design)). A group named in `items` still needs what it needs without it (Undo needs the source's `undo`, Merge & Center and AutoSum need `sheet`); an unknown or repeated group is skipped.

A host's button is an object, `{ id, label, icon?, run?, menu?, disabled?, pressed?, group?, size? }`. The toolbar draws it as its own buttons: `label` is the tooltip and the accessible name, `icon` a Vue component (it gets the class `xs-icon`) or SVG markup, drawn at the toolbar's icon size, and without an icon the label is the button's text. A click closes the toolbar's menus and calls `run`; `disabled` and `pressed` are the host's, so a host that passes a reactive array updates them. Buttons next to each other in `items` form one group, unless `group` splits them: buttons next to each other with the same `group` form one group, as a group of Excel's ribbon, and a different value (or none after one) starts another, so a host lays out a tab of its own as Excel's groups. A `group` named as a group of the toolbar's own that `rows: 2` stacks (`undo`, `formatPainter`, `autoSum`, `pivotTable`, `refreshAll`, `pivotAnalyze`, `pivotDesign`) joins that group where the button is next to it in `items`, as Insert Function joins AutoSum in Excel's Function Library; Font, Alignment and Number, laid out in Excel's rows, take no host's button. `size: 'large'` draws the button as tall as both rows of `rows: 2`, with `label` under its icon, as Excel's PivotTable ([below](#two-rows-as-excels-ribbon)); elsewhere it is drawn as the others. Each has the hook `data-tb-host="<id>"`. With `menu`, a list of `{ id, label, run, disabled? }`, the toolbar draws the button's list as its own (in the narrow menu too): without `run` a click opens it, as Excel's Conditional Formatting does, and with `run` the button is split, as AutoSum: its part runs `run`, its arrow (`data-tb-host-menu="<id>"`) opens the list. An item runs and closes the list; its hook is `data-tb-host-item="<id>"`.

```vue
<script setup lang="ts">
import { onUnmounted, ref } from 'vue'
import { SheetToolbar, SheetView, TOOLBAR_GROUPS, type SheetViewApi, type SheetViewState, type ToolbarItem } from '@xlcalc/vue'
import { localSource } from '@xlcalc/vue/local'
import '@xlcalc/vue/style.css'

const source = localSource({ sheets: [{ name: 'Sheet1', cells: { B2: { value: 120 }, B3: { value: 80 } } }] })
onUnmounted(() => void source.close())

const state = ref<SheetViewState | null>(null)
const sheet = ref<SheetViewApi | null>(null)
// No borders or colors; AutoSum first; the host's Save button at the end, drawn as the toolbar's own
const items: ToolbarItem[] = [
  'autoSum',
  ...TOOLBAR_GROUPS.filter((g) => g !== 'autoSum' && g !== 'borders' && g !== 'colors'),
  { id: 'save', label: 'Save', icon: '<svg viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2"><path d="M5 3h11l3 3v15H5z"/><path d="M8 3v6h8V3"/></svg>', run: () => void source.book() },
]
</script>

<template>
  <SheetToolbar :source="source" :sheet="sheet" :state="state" :items="items" />
  <SheetView :source="source" ref="sheet" style="height: 360px" @state="state = $event" />
</template>
```

At any width the toolbar is one row: it keeps in the row the items that fit, in the order `items` gives them, and moves the rest, the host's buttons included, into the menu under a More button at its end, in order, rather than onto a second line: it measures the row with every item and keeps, in order, each group that still fits beside More: a group too wide for what is left goes into More and the groups after it still take the row while they fit, so the row and the menu each keep the order of `items`. At 600 px and wider a group is Excel's: the blocks of Excel's Font (`font`, `fontStyle`, `borders`, `colors`), Alignment (`verticalAlign`, `orientation`, `align`, `merge`) and Number (`number`, `formatCells`) groups that follow each other in `items` stay or go together, so Format Cells never stays without the Number group, nor Merge & Center without the alignments; a host's group (its buttons with the same `group`, with the toolbar's group it joins) stays or goes whole too. Where Excel's Font group does not fit on the row, each block fits on its own, with Bold, Italic and Underline kept over the Font boxes when only one of them can stay (a run of a host's buttons with the same `group` is one block, apart from the toolbar's group it joins): with the default items a phone keeps Undo, Redo, Format Painter, Bold, Italic and Underline, while the Font boxes go into More with what follows that does not fit; a host's few buttons after `undo` stay in the row. When every item fits there is no More button. It measures again when its width, the items, `rows` or the texts change.

`rows` lets the items take more lines, except on a phone (a touch screen below 600 px). It is 1 by default. With 2 the toolbar is laid out as Excel's ribbon ([below](#two-rows-as-excels-ribbon)). Any other number wraps the row onto that many lines in order, a group whole onto the next line, and only what does not fit on them goes into More, which then ends the last line; a group that starts a line has no separator before it, and `Infinity` wraps every item, with no More button. On a phone the toolbar keeps one line whatever `rows` says, since its 44 px targets would take the sheet's height; a host that wants other lines at other widths passes its own `rows` (`:rows="wide ? 2 : 1"`). A group wider than a line goes into More with what follows it, rather than spilling out of the toolbar.

### Two rows, as Excel's ribbon

With `rows: 2` (except on a phone) the toolbar is one sequence of groups, each two rows tall with a separator between groups, laid out as Excel for Windows lays out its Home tab (measured at 1280 px):

- Font: the Font and Font Size boxes with Increase and Decrease Font Size on the first row, Bold, Italic, Underline, Borders, Fill Color and Font Color on the second. The blocks `font`, `fontStyle`, `borders` and `colors` form this one group where they follow each other in `items`.
- Alignment: Top, Middle and Bottom Align and Orientation on the first row, Align Left, Center, Align Right and the indents on the second, then Wrap Text over Merge & Center, from `verticalAlign`, `orientation`, `align` and `merge` (measured again at 1920 px, where Excel draws Orientation over the indents).
- Number: the Number Format box on the first row, its buttons on the second, and Format Cells at the end of the second row, where Excel has the group's dialog launcher, from `number` and `formatCells`.
- The other groups stack their buttons two to a column, the first at the top, as Excel stacks its small buttons: Undo over Redo (as on Excel's Draw tab), Format Painter and AutoSum at the top of their columns, PivotTable Analyze's commands two to a column. PivotTable, Refresh All and Design's Subtotals, Grand Totals, Report Layout and Blank Rows are Excel's large buttons, as tall as both rows: the icon at the size of every other button's and the button's name under it, as Excel's ribbon draws it. The name is the button's ScreenTip without its key (`Refresh All`, not `Refresh All (Ctrl+Alt+F5)`); one word takes one line and more take two, broken where the longer line is shortest, as Excel breaks them (`Промежуточные` over `итоги`). A list's arrow follows the name, on a second line of its own after one word (Subtotals); a split button's part is the icon and its arrow is the name with the arrow under it, as Excel's Refresh All. The button is as wide as the longer line of its name, which is never cut, as Excel widens its Watch Window for `Окно контрольного` over `значения`, and the row is measured with the names, so a group they widen goes into More sooner. The name is only shown: the button's accessible name stays its `aria-label`. On one line and in More a large button is drawn as the others, without its name. A host's run of buttons is a group of its own, stacked the same way, or several, one for each `group` ([above](#choosing-the-buttons)), and a host's button with `size: 'large'` is a large button too, its `label` the name under its icon. A large button takes a column of its own, so a small button left at the top of a column before it stays alone there; the buttons keep the order of `items`, down each column, then across, and Tab takes them in that order.

A host's Formulas tab, as Excel's Function Library, Defined Names, Formula Auditing and Calculation groups (`icon`s left out):

  { id: 'defineName', label: 'Define Name', run: defineName, group: 'names' },

With `rows: 1` the same groups go into More whole.

Within one of these groups Excel's places win over the order of `items` (`['fontStyle', 'font']` draws the Font boxes over Bold). A run of them whose first column of rows is not full (`fontStyle` alone, `align` alone, `verticalAlign` with `merge`) stacks its buttons two to a column instead, leaving no hole, and blocks of one Excel group that do not follow each other in `items` are separate groups. When the groups do not fit, whole groups go into More, none split between the row and the menu, as on one line: a group too wide for what is left goes there and later groups still take the row while they fit. The menu draws their blocks in the order of `items`, each Excel group on one line, as with `rows: 1`. Below 600 px the toolbar keeps one line, and on a touch screen the rows are 44 px tall.

## `FormatDialog`

`SheetView` has its own Excel Format Cells dialog when the source has `format`: Ctrl+1 opens it (on a Mac as well, since the browser reserves Cmd+1), as do the sheet's `formatCells()` and the toolbar's Format Cells… with `sheet`, and OK formats the selection through the sheet's `format`. It opens on the tab it was last on; `formatCells(at)` opens it at `at`, a tab (`FormatCellsTab`) and on the Number tab an item of its list picked, as the toolbar's More Accounting Formats... (`{ tab: 'number', choice: 'accounting' }`) and Format Cell Alignment (`{ tab: 'alignment' }`) open it. The dialog is also exported as `FormatDialog`, for a host that places its own. It is Excel's Format Cells for the selection reported by the sheet's `state` event, with the tabs whose settings xlcalc's cell style supports:

- Number is Excel's Number Format box: the category of the code in the input, the list's items (an item puts its format's code in the input) and the code itself, which may be any code.
- Alignment has the horizontal and vertical alignment, the indent (with Left, Right and Distributed alignment, as in Excel), text wrapping, and Orientation: Degrees, a whole number from -90 to 90 (up for positive ones), and Vertical Text, which stacks the letters and sets the degrees aside, as Excel's Text box does. They are xlcalc's `AlignmentStyle.rotation` (0.66.0), a number or `'vertical'`; 0 removes it.
- Font has the font name, Regular, Italic, Bold or Bold Italic, the size, the underline, strikethrough and the color.
- Border has the line style and color, the presets None, Outline and Inside, and a button for each edge around a preview, the inside ones for a selection of more than one row or column.
- Fill has the background color.
- Protection has Locked and Hidden with Excel's note: a cell is locked and its formula shown unless its style says otherwise, and neither matters until the sheet is protected ([protection.md](protection.md)). On a protected sheet both are disabled, since Excel does not change them there.

Colors come from Excel's palette, as on the toolbar, or can be any `#RRGGBB`. The dialog opens with the active cell's formatting; for a single cell the edges show its own borders, and for a range they show as unknown, grayed out as in Excel. OK emits `apply` with patches for `SheetView.format` covering only what changed: the font, the alignment, the fill, the protection and the number format over the selection, and each border edge on its row or column (of every range of a selection of several, `state.areas`), or on the cells on both sides of an inside line (a single patch over every cell when all edges use the same line), all in one call and therefore a single undo step; then it emits `close`, as Cancel, Esc and a click outside the dialog do. Tab and Shift+Tab stay inside it. An input beyond Excel's limits (a size of 1 to 409 points, an indent of 0 to 250) or an invalid color code blocks OK. On a phone the dialog takes the full screen with 44 px targets.

A host with its own dialog listens to the toolbar's `formatCells` event, which the button, More Accounting Formats... and Format Cell Alignment then emit instead, the items with where the dialog opens, which the host passes as `FormatDialog`'s `at` (a host whose listener the toolbar cannot see, such as a custom element, also sets `hostDialog`):

```vue
<script setup lang="ts">
import { onUnmounted, ref } from 'vue'
import { FormatDialog, SheetToolbar, SheetView, ruMessages, type FormatCellsAt, type SheetViewApi, type SheetViewState } from '@xlcalc/vue'
import { localSource } from '@xlcalc/vue/local'
import '@xlcalc/vue/style.css'

// A workbook in ru-RU: its locale module loads when the source opens
const source = localSource({ locale: 'ru-RU', sheets: [{ name: 'Лист1', cells: { A1: { value: 1234.5 }, A2: { value: 0.25 } } }] })
onUnmounted(() => void source.close())

const state = ref<SheetViewState | null>(null)
const sheet = ref<SheetViewApi | null>(null)
const formatOpen = ref(false)
const formatAt = ref<FormatCellsAt | null>(null)
function openFormat(at?: FormatCellsAt): void {
  formatAt.value = at ?? null
  formatOpen.value = true
}
</script>

<template>
  <SheetToolbar :source="source" :sheet="sheet" :state="state" :messages="ruMessages" @format-cells="openFormat" />
  <SheetView :source="source" ref="sheet" :messages="ruMessages" style="height: 360px" @state="state = $event" />
  <!-- The host's own dialog, placed by the host: OK formats through the sheet -->
  <FormatDialog :open="formatOpen" :at="formatAt" :state="state" :messages="ruMessages" @apply="sheet?.format($event)" @close="formatOpen = false" />
</template>
```

Fill patterns, diagonal borders, shrink to fit, merging, text direction, superscript, subscript and the Protection tab are not available, since xlcalc's cell style does not support them. Excel's dial for the degrees is not drawn; the degrees are typed.

### Rotated text

A cell whose style has `alignment.rotation` is drawn as Excel orients its text: at an angle, the line turned counterclockwise by positive degrees and clockwise by negative ones, about the middle of the box it takes when turned, and that box aligned in the cell by the cell's horizontal and vertical alignment as level text is; `'vertical'` stacks the letters one above the other. The box is measured in the cell's font on a canvas (estimated where the browser has none). Unlike Excel, rotated text does not overflow into empty neighbors and does not wrap, borders are not slanted with text at an angle, and a hyperlink's text stays level: the text is clipped to its cell. The row's height and the text are the source's: `./local` (xlcalc 0.67.0) fits a row to its rotated text as Excel for Mac does, when text is typed into a rotated cell, when Format Cells or the toolbar's Orientation rotates text, and on AutoFit, unless the row's height was set by hand, and the sheet reads the heights again; a rotated cell shows its text as Excel's widest column would, so a number turned in a narrow column shows all its digits rather than `####`.
